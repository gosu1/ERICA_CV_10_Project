## 내가 맡은 일과 성과

- **판정 프로그램:** 카메라 영상에서 사람을 찾아 신호등 색을 정하는 `server.py`를 만들었습니다. 22분 영상 659장을 정답과 비교해 656장(99.5%)이 맞았고, 공부 중인 룸에 초록불이 잘못 켜진 경우는 없었습니다. → [01_판정코드](10_Project/프로젝트_최종/통합%20코드모음/01_판정코드)
- **모델 비교:** 사전학습 YOLO 15종을 우리 영상과 합성 사진으로 비교해 YOLO26s와 기준값 0.30을 골랐습니다. YOLO26s는 연산량이 YOLO11x의 9분의 1이면서, 합성 엎드린 장면 40장을 모두 잡은 점과 실제 영상의 사람 최저 신뢰도가 YOLO11x와 같았습니다. → [EXPERIMENTS.md](10_Project/프로젝트_최종/통합%20코드모음/02_데이터·실험/EXPERIMENTS.md)
- **생성형 데이터 실험:** Stable Diffusion으로 엎드린 사람 사진 80장을 합성해, 모델이 후드를 쓰고 엎드린 사람에게 약하다는 점을 찾았습니다. 이 결과로 시범 수집에서 먼저 모을 장면을 정했습니다. → [synthetic](10_Project/프로젝트_최종/통합%20코드모음/02_데이터·실험/synthetic)
- **그 밖의 작업:** 공개 데이터셋 10종을 조사했고, RTSP 카메라 영상을 실시간으로 인식하는 화면(초당 17.8장)을 만들었습니다.
- **회의 보고서:** 1차·2차 회의 보고서를 팀원과 함께 작성했습니다.

자세한 내용은 [최종보고서](10_Project/프로젝트_최종/최종보고서/최종보고서.pdf) 11쪽부터 실은 개인 연구 보고에 있습니다.

- **사람·물건 라벨은 자동 라벨입니다:** yolov10s가 만든 라벨(기준 0.35, 엎드린 사진은 0.2)이고, 눈으로 검수한 것은 테이블뿐입니다.
- **작은 물체가 많습니다:** 마우스, 휴대폰, 컵은 화면의 0.3%보다 작습니다.

### 성능 지표

| 평가 | 데이터 | 지표 | 파인튜닝 전 YOLO26s | 파인튜닝 v2 |
|---|---|---|---|---|
| 학습 중 검증 | 검증 90장, 10개 클래스 | precision / recall / mAP50 / mAP50-95 | - | 0.768 / 0.741 / 0.813 / 0.749 |
| 테이블 | 1차 영상 뒤 20% 131장 | 정답 박스와 IoU 0.5 이상 | 2/131 (2%) | 131/131 (100%), 평균 IoU 0.976 |
| 테이블 | 웹캠 영상 36장 | 정답 박스와 IoU 0.5 이상 | 0% | 100%, 평균 IoU 0.955 |
| 엎드린 사람 | 1차 영상 마지막 84프레임 (7초) | 신뢰도 0.35 이상 | 78/84 (92.9%) | 84/84 (100%) |
| 사람·물건 | 웹캠 영상 36장 | 정답 개수 대비 검출 비율 | 사람 100%, 가방 100% | 사람 100%, 가방 0% |
| 신호등 판정 | 1차 영상 659장 (v2는 학습에 안 쓴 132장) | 정답 색과 같은 장 수 | 656/659 (99.5%) | 131/132 |

지표를 읽을 때 주의할 점은 다음과 같습니다.

- **검증 점수는 높게 나옵니다:** 검증 90장은 학습 프레임 사이에서 뽑았습니다. 1차 영상의 검증 프레임은 가장 가까운 학습 프레임과 2초밖에 떨어져 있지 않아서, 같은 장면을 다시 본 점수에 가깝습니다.
- **평가한 체크포인트:** 평가에는 mAP50-95가 가장 높았던 17에포크 모델(best.pt)을 썼습니다. 마지막 25에포크에서는 precision이 0.586까지 떨어졌습니다.
- **테이블 100%의 범위:** 카메라가 고정이라 모든 프레임에 같은 정답 박스를 썼고, 학습에도 같은 박스를 썼습니다. 그래서 이 100%는 이 카메라 위치에서 맞힌 값입니다.
- **엎드린 사람 100%의 범위:** 84프레임은 1명이 7초 동안 엎드린 한 장면입니다.
- **클래스별 검증 결과:** 혼동 행렬에서 사람과 테이블은 거의 다 맞혔습니다. 휴대폰과 마우스는 서로 헷갈린 경우가 있었고, 가방 일부는 핸드백으로 잡혔습니다.

## 결론의 한계

- **빈 책상 판정:** 팀 통합 실행 코드는 감지 영역에 사람도 짐도 10초 동안 보이지 않으면 바로 초록을 켭니다. 그런데 짐을 찾는 최종 모델 v2는 웹캠 영상에서 가방을 0% 잡았고(위 성능 지표), 외투는 코드가 짐으로 보는 11종에 들어 있지 않습니다. 그래서 가방이나 외투만 두고 잠깐 나간 자리에 초록이 바로 켜질 수 있습니다. 코드는 가방 기준값을 0.10으로 낮춰 두었지만, 그 기준에서 가방을 얼마나 잡는지는 재지 않았습니다. 시범 운영에서는 짐이 있는데 빈 책상으로 본 경우를 "주인이 있는데 초록"과 같은 기준(0건)으로 확인해야 하고, 그 전까지는 빈 책상도 잠시 기다린 뒤 초록을 켜는 편이 안전합니다.
- **대시보드 효과:** 저녁 식사 시간 활성화율 22% → 50%는 실측값이 아닙니다. 판정은 1차 영상을 v2로 돌린 실제 결과지만, 14개 룸의 출입 시각은 현장 관찰을 바탕으로 만든 시나리오입니다. 그리고 "초록이 켜지면 5분 안에 다른 학생이 짐을 옮기고 들어온다"는 가정이 들어 있습니다. 발표 화면의 값은 추천 시나리오(시드 #378) 하나에서 나왔고, 시드 300개 평균은 26% → 51%입니다. 실제 효과는 시범 운영에서 초록이 켜진 뒤 다른 학생이 들어오기까지 걸린 시간을 재서 확인해야 합니다.

## 실행 방법

Python과 pip가 설치되어 있어야 합니다. 원본 촬영 영상은 사람이 나와서 올리지 않았으므로, 웹캠이나 직접 찍은 영상으로 실행합니다.

1. 패키지를 설치합니다.
   ```bash
   pip install ultralytics opencv-python pillow
   ```
2. 실행 폴더로 이동합니다.
   ```bash
   cd "10_Project/프로젝트_최종/통합 코드모음/06_통합실행"
   ```
3. 웹캠으로 사람 인식이 되는지 확인합니다. 시작할 때 초록불 시간을 물으면 Enter를 누릅니다.
   ```bash
   python 성능확인.py
   ```
   결과: 창에 판정 결과와 처리 속도가 표시됩니다. `q`를 누르면 끝납니다.
4. 영상 하나를 룸 여러 개처럼 복제해 판정을 시험합니다. 테이블이 보이는 천장 각도 영상이어야 감지 범위가 잡힙니다. 초록불 시간을 물으면 `00:01:30`처럼 짧게 입력합니다.
   ```bash
   python 알박기_실행.py --demo-video 내영상.mp4 --demo-rooms 3 --open
   ```
   결과: 브라우저에 현황 화면(http://localhost:8800)이 열리고, 룸마다 신호등 색이 바뀝니다.
5. 실제 카메라로 운영하려면 `rooms.example.json`을 `rooms.json`으로 복사해 룸별 카메라 주소를 적은 뒤 실행합니다.
   ```bash
   python 알박기_실행.py --rooms rooms.json --limit 00:30:00
   ```

판정 모델(`03_모델/알박기_yolo26s_v2.pt`)은 레포에 들어 있고, SAM 가중치는 처음 실행할 때 자동으로 받습니다. 그 밖의 옵션은 [06_통합실행/README.md](10_Project/프로젝트_최종/통합%20코드모음/06_통합실행/README.md)에 있습니다.

공개 레포라서 실제 사람이 나오는 이미지는 모두 모자이크했고, 영상은 올리지 않았습니다.
